7주차 — 열린재정 데이터 활용

skill 기반 전처리와 tidy data

먼저 회고


처음에는 각자 실제 업무에 가까운 프로젝트를 골랐습니다.


그런데 실무에 도움이 되려면 공개하기 어려운 자료가 필요했습니다.


학습 저장소와 외부 LLM 환경에서는 그 자료를 안전하게 다룰 수 없습니다.


그래서 개별 프로젝트는 지침 작성 연습 으로 마무리하고, 본격 실습은 공개 데이터 팀 프로젝트 로 전환했습니다.

열린재정 데이터의 장점


열린재정 데이터는 모두가 같은 자료를 볼 수 있습니다.


  • 공개 데이터라 함께 검토 가능
  • 수집 조건과 표 구조가 비교적 명확함
  • 수작업 절차를 자동화하기 좋음
  • 계산식과 검증 기준을 세우기 좋음

열린질문 테스트 회고


정부 제공 생성형 AI 서비스는 어땠나요?


이 서비스의 장단점에 대해 논의합니다.

W6 에 사람이 먼저 한 일


지난주에는 바로 자동화하지 않았습니다.


사람이 먼저 열린재정 사이트에서 자료를 찾고, 엑셀로 내려받고, 필요한 열과 계산식을 확인했습니다.

W6 workflow


지난주 사람이 직접 한 일은 세 단계였습니다.


Step 1. 열린재정 웹사이트에서 자료를 쿼리하고 엑셀로 다운로드


Step 2. 다운로드한 엑셀 데이터를 피벗 테이블로 변환


Step 3. 피벗 테이블에서 집행률 계산


오늘은 이 workflow 를 에이전트가 도울 수 있는 형태로 다시 나눕니다.

1. Workflow 를 쪼개기

그대로 자동화하기 어려운 이유


W6 workflow 는 사람에게는 자연스럽지만, 에이전트에게는 여러 일이 한 덩어리로 섞여 있습니다.


  • 웹사이트에서 조건을 선택한다
  • 엑셀 파일을 다운로드한다
  • 표를 피벗 테이블로 바꾼다
  • 집행률 계산식을 추가한다
  • 결과를 해석한다


그래서 자동화하려면 반복 가능한 일 과 사람이 판단할 일 을 나눠야 합니다.

오늘의 분리 기준


구분 에이전트가 맡기 좋은 일 사람이 맡아야 하는 일
수집 같은 조건으로 데이터 가져오기 조건이 업무 목적에 맞는지 판단
전처리 CSV 형태로 정리하기 열 의미와 금액 단위 확인
분석 계산 후보와 절차 제안 피벗 구성과 결과 해석
검증 행 수·합계 점검 이상한 결과의 업무적 의미 판단


에이전트가 하는 일은 반복이고, 사람이 하는 일은 판단입니다.

데이터 형태도 바꿉니다


W6 에서는 엑셀 파일을 바로 피벗 테이블로 만들었습니다.


W7 에서는 중간에 tidy CSV 를 둡니다.


열린재정 데이터
  -> raw bundle
  -> tidy CSV
  -> Excel 피벗 테이블
  -> 집행률 분석


CSV 는 엑셀에서도 열 수 있고, 에이전트도 다시 읽기 쉽습니다.

2. 준비한 4가지 skill

4가지 skill: 안내와 조율


오늘은 skill 이름을 외우는 시간이 아닙니다.


각 skill 이 workflow 의 어느 부분을 맡는지만 알면 됩니다.


사용자 안내

open-fiscal-guide


무엇을 하려는지 정리하고, 필요한 다음 단계를 안내합니다.

전체 흐름 조율

open-fiscal-pipeline


수집, 전처리, 분석 설계 중 어느 단계가 필요한지 판단합니다.

4가지 skill: 수집과 변환


반복 가능한 데이터 준비는 두 skill 이 맡습니다.


열린재정 자료 수집

open-fiscal-settlement-fetcher


열린재정 데이터를 가져오고 raw bundle 을 남깁니다.

tidy CSV 변환

open-fiscal-settlement-processor


raw 데이터를 엑셀에서 열 수 있는 tidy CSV 로 바꿉니다.

Skill 이 해주는 범위


오늘 skill 로 할 수 있는 일은 여기까지입니다.


  • 열린재정 웹사이트/API 에서 필요한 데이터를 가져온다
  • 원본에 가까운 raw 데이터를 남긴다
  • 엑셀에서 열 수 있는 tidy CSV 파일로 변환한다
  • 수집 조건, 행 수, 합계 같은 검증 정보를 남긴다


skill 의 목표는 “보고서 완성” 이 아니라 분석 가능한 표 만들기 입니다.

학습자가 이어서 할 일


CSV 가 만들어진 뒤부터는 사람이 엑셀에서 이어갑니다.


단계 학습자가 할 일

검토 결과가 업무적으로 말이 되는지 확인
확장 다음 분석 질문 정하기


오늘 자동화는 학습자를 대체하지 않습니다. 학습자가 분석을 시작할 수 있는 표를 준비합니다.

3. 오늘의 데모

데모 흐름


오늘은 API 호출을 줄이기 위해 범위를 작게 잡습니다.


2024년 교육부 데이터 만으로 workflow 를 확인합니다.


  1. 예시 프롬프트 실행
  2. 생성된 폴더를 탐색기에서 열기
  3. CSV 파일을 엑셀로 열기
  4. 피벗 테이블과 집행률 분석 추가


에이전트 작업이 끝난 지점이 사람 분석의 시작점입니다.

예시 프롬프트


열린재정 세출/지출 결산현황 데이터 중 2024년 교육부 자료만 수집하고,
엑셀에서 피벗 테이블로 분석할 수 있도록 tidy CSV 파일로 변환해줘.

API 호출을 줄이기 위해 2024년, 소관=교육부 범위로만 실행해줘.

작업 후에는 생성된 폴더 위치, CSV 파일명, 행 수,
그리고 사람이 엑셀에서 확인해야 할 항목을 정리해줘.

실행 후 확인할 것


에이전트가 파일을 만들었다고 끝이 아닙니다.


확인 항목 볼 것
폴더 raw 와 processed 가 생성됐는가
CSV 엑셀에서 한글과 열 이름이 잘 열리는가
범위 2024년 교육부 자료만 들어 있는가
행 수 이 범위의 수집 행 수와 변환 행 수가 설명되는가
금액 주요 금액 열이 숫자로 읽히는가

피벗 테이블에서 볼 질문


피벗 테이블은 정답을 주는 도구가 아니라, 질문을 빠르게 바꾸는 도구입니다.


  • 교육부 안에서 회계별 지출 규모는 어떻게 다른가?
  • 분야·부문별 지출계획현액과 지출순액은 어떻게 다른가?
  • 분야별로 집행률 차이가 보이는가?
  • 집행률이 낮은 항목은 어떤 공통점이 있는가?


질문을 바꾸면서 피벗 구성을 바꿔 봅니다.

집행률 계산


오늘 사용할 기본 계산식입니다.


집행률 = 지출순액 / 지출계획현액


확인할 점:

  • 지출계획현액이 0인 행은 어떻게 처리할 것인가
  • 금액 단위가 연도별로 같은가
  • 평균을 낼 때 단순 평균과 금액 가중 평균 중 무엇이 맞는가
